## 🤝 **Contribuer à la Documentation**

La documentation est **open source** tout comme le projet !

### 🎯 **Comment contribuer ?**

1. **Trouver un problème** :
   - Une information manquante
   - Une explication peu claire
   - Une erreur dans un exemple de code
   - Une faute de frappe

2. **Créer une branche** :
   ```bash
   git checkout -b docs/fix-nom-du-probleme
   ```

3. **Faire les modifications** :
   - Modifier le fichier Markdown concerné
   - Respecter le style existant

4. **Créer une Pull Request** :
   - Ciblez la branche `main` ou `develop`
   - Utilisez le prefix `docs:` dans votre message de commit

### 🎯 **Règles pour la Documentation**

- **Langage simple** : Évitez le jargon technique non expliqué
- **Exemples concrets** : Toujours inclure des exemples de code tirés du projet
- **Structure claire** : Utilisez les titres et sous-titres appropriés
- **Diagrammes** : Utilisez Mermaid pour les architectures
- **Liens** : Liez les pages entre elles pour une navigation fluide
